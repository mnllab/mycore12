## 1. 기본 문체

결과지는 **전문가가 옆에서 쉽게 설명해 주는 말**처럼 쓴다.
논문·보고서·심리검사 해설서 문체를 쓰지 않는다.

원칙 다섯 가지.

1. **한 문장에 핵심 하나만** 담는다.
2. 쉼표로 계속 잇지 말고 **두 문장으로 나눈다**.
3. 추상적 설명 대신 **실제 장면**을 보여준다.
4. 평가하지 않고 **관찰하듯** 쓴다.
5. 같은 문단에서 같은 표현을 반복하지 않는다.

### 톤

사용자를 규정하지 않는다. "당신은 이런 사람입니다"를 반복하지 않는다.

```
쓴다:   평소에는…
        이런 상황에서 힘이 잘 살아납니다.
        일이 복잡해질수록…
        이럴 때 다른 에너지를 함께 써보면 좋습니다.

안 쓴다: 당신은 ~한 사람입니다.
        ~하는 경향이 두드러집니다.
        ~한 특성을 보유하고 있습니다.
```

## 2. 가운데점 사용 원칙

**가운데점(·)은 원칙적으로 쓰지 않는다.**

### 허용 (예외 2곳뿐)

| 위치 | 표기 |
|---|---|
| 브랜드 락업 | `마이코어12 · MYCORE12` |
| 에너지 서명 구분자 | `숙고 × 조율 × 구체` (× 사용, · 아님) |

### 금지

제목과 본문에서 개념을 나열할 때 쓰지 않는다.

| 쓰지 않음 | 대신 |
|---|---|
| 업무·의사결정 | 일할 때의 모습 / 판단할 때의 모습 |
| 관계·협업 | 사람들과 함께할 때 |
| 계획·실행 | 일을 계획하고 움직일 때 |
| 분석·통합 | 나눠 보는 힘과 이어 보는 힘 |
| 성장·확장 | 나를 더 넓게 쓰는 방법 |
| 스트레스·회복 | 힘들 때와 다시 돌아올 때 |

### 나열이 꼭 필요할 때

세 개 이상을 나열해야 하면 **쉼표**를 쓰고, 마지막은 "그리고"로 잇는다.

```
전:  숙고 · 조율 · 구체 · 분석 · 명료 · 유연 에너지를 사용합니다.
후:  숙고, 조율, 구체, 분석, 명료, 유연.
     이 여섯 가지를 평소에 더 편하게 씁니다.
```

```

**나누는 지점**: "~하고", "~한 뒤", "~하며", "~하면서" 가 나오면
그 자리에서 문장을 끊을 수 있는지 먼저 본다.

후: 무엇이 무엇을 만들었는지 짚어보고 판단합니다.
```

**11.**
```
전: 개인의 결론과 함께 결정에 영향을 받는 사람의 관점과 수용 가능성까지
    고려합니다.
후: 내 결론만 보지 않습니다.
    이 결정에 영향받는 사람이 어떻게 받아들일지도 함께 봅니다.
```

### relationshipStyle

**12.**
```
전: 관계에서는 의견 차이를 줄이고 서로 편하게 협력할 수 있는 흐름을
    만드는 데 강점이 있습니다.
후: 생각이 갈릴 때 서로 맞는 지점을 잘 찾습니다.
    같이 일하기 편한 분위기를 만듭니다.
```

**13.**
```
전: 관계에서는 상대가 원하는 소통의 속도와 형태를 확인하면 자신의 관계
    강점을 더 안정적으로 활용할 수 있습니다.
후: 상대가 편한 속도를 한 번 물어보면 좋습니다.
    그럴수록 대화가 더 잘 풀립니다.
```

### teamContribution

**14.**
```
전: 팀에서 숙고의 행동 리듬, 조율의 협업 방식, 구체의 사고 접근,
    분석의 판단 관점, 명료의 관계 방식, 유연의 운영 방식을 하나의 일관된
    패턴으로 제공합니다.
후: 팀에서 이 여섯 가지가 한 사람 안에서 함께 움직입니다.
    살펴보고, 맞추고, 구체적으로 만들고, 나눠 보고, 분명히 말하고,
    상황에 맞게 바꿉니다.
```

**15.**
```
전: 팀에서는 회의, 탐색, 결정, 실행, 회고 단계마다 필요한 보완 에너지를
    선택적으로 더할 때 기여도가 높아집니다.
후: 회의할 때, 정할 때, 움직일 때 필요한 힘이 조금씩 다릅니다.
    그때그때 하나씩 더해보면 도움이 됩니다.
```

### cautions

**16.**
```
전: 숙고가 과도해지면 충분한 정보가 모일 때까지 시작을 미루거나
    결정 시점을 놓칠 수 있습니다.
후: 살피는 마음이 커지면 시작이 늦어질 수 있습니다.
    정할 때를 놓치기도 합니다.
```

### goodFitSituations

**17.**
```
전: 복잡한 영향과 위험을 미리 살펴야 하는 중요한 의사결정
후: 미리 잘 살펴야 하는 중요한 선택
```

### collaborationGuide

**18.**
```
전: 숙고 에너지를 자연스럽게 사용할 수 있도록 행동의 속도와 결정 범위가
    명확할 때
후: 언제까지 정하면 되는지 분명할 때
```

**19.**
```
전: 먼저 잘 작동한 행동을 구체적으로 짚고, 다음에는 추진 에너지를 한 번 더
    적용해 보도록 제안하는 방식이 효과적입니다.
후: 잘된 점을 먼저 짚어주면 좋습니다.
    그다음 "이건 바로 해봐도 좋겠다"고 말해주면 잘 통합니다.
```

### developmentRoadmap

**20.**
```
전: 4주 동안 행동(숙고↔추진), 관계(명료↔공감), 운영(유연↔원칙) 세 축을
    매주 한 가지씩 연습하세요. 자연스러운 에너지를 억제하지 말고,
    보완 에너지를 추가했을 때 결과가 좋아진 장면을 기록하세요.
후: 한 달 동안 매주 하나씩만 연습해 보세요.
    첫 주는 바로 시작해 보기, 둘째 주는 상대 마음 먼저 물어보기,
    셋째 주는 정한 기준 지켜보기입니다.
    원래 방식을 참을 필요는 없습니다.
    새로 더해봤더니 좋았던 순간만 적어두면 됩니다.
```

## 10. 개편 순서 제안

작업량이 크므로 파일럿을 먼저 둔다.

1. **파일럿 2유형** (`000000`, `111111`) 전체 필드 개편 → 문체 확정
2. 필드 단위 일괄 개편 — 짧은 항목부터
   `goodFitSituations` → `strengths` → `cautions` → `stressSignals`
3. 긴 서술 필드 개편
   `workStyle` → `decisionStyle` → `relationshipStyle` → `teamContribution`
4. `overview` / `encouragement` (가운데점 960회가 집중된 곳)
5. `developmentGuide` / `developmentRoadmap` / `collaborationGuide`
6. 제목 개편 (§7) — UI 코드 함께 수정
7. 전수 검증 (§9) 후 `v2.2` 로 버전 승격
